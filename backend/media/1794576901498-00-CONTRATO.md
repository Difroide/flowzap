(protocolo Baileys/QR, grátis) como camada de conexão, **motor de fluxos próprio** (Node + BullMQ)
e **interface própria** (React + React Flow).

## Schema do banco (PLANO 1 cria `schema.sql`; PLANOS 2 e 3 só consomem)

```sql
CREATE TABLE IF NOT EXISTS instances (
  id SERIAL PRIMARY KEY,
  name TEXT UNIQUE NOT NULL,
  phone TEXT,
  status TEXT NOT NULL DEFAULT 'disconnected',
  created_at TIMESTAMPTZ DEFAULT now()
);

CREATE TABLE IF NOT EXISTS flows (
  id SERIAL PRIMARY KEY,
  name TEXT NOT NULL,
  description TEXT,
  status TEXT NOT NULL DEFAULT 'draft',
  instance_name TEXT,
  trigger_type TEXT NOT NULL DEFAULT 'all',
  trigger_keywords TEXT[] NOT NULL DEFAULT '{}',
  created_at TIMESTAMPTZ DEFAULT now(),
  updated_at TIMESTAMPTZ DEFAULT now()
);

CREATE TABLE IF NOT EXISTS flow_nodes (
  id SERIAL PRIMARY KEY,
  flow_id INT NOT NULL REFERENCES flows(id) ON DELETE CASCADE,
  node_type TEXT NOT NULL,
  name TEXT,
  position_x REAL NOT NULL DEFAULT 0,
  position_y REAL NOT NULL DEFAULT 0
);

CREATE TABLE IF NOT EXISTS flow_node_actions (
  id SERIAL PRIMARY KEY,
  node_id INT NOT NULL REFERENCES flow_nodes(id) ON DELETE CASCADE,
  action_type TEXT NOT NULL,
  config JSONB NOT NULL DEFAULT '{}',
  sort_order INT NOT NULL DEFAULT 0
);

CREATE TABLE IF NOT EXISTS flow_connections (
  id SERIAL PRIMARY KEY,
  flow_id INT NOT NULL REFERENCES flows(id) ON DELETE CASCADE,
  from_node_id INT NOT NULL REFERENCES flow_nodes(id) ON DELETE CASCADE,
  to_node_id INT NOT NULL REFERENCES flow_nodes(id) ON DELETE CASCADE,
  condition_config JSONB NOT NULL DEFAULT '{"type":"always"}'
);

CREATE TABLE IF NOT EXISTS contacts (
  id SERIAL PRIMARY KEY,
  phone TEXT NOT NULL,
  instance_name TEXT NOT NULL,
  name TEXT,
  custom_fields JSONB NOT NULL DEFAULT '{}',
  tags TEXT[] NOT NULL DEFAULT '{}',
  created_at TIMESTAMPTZ DEFAULT now(),
  UNIQUE (phone, instance_name)
);

CREATE TABLE IF NOT EXISTS contact_flow_states (
  id SERIAL PRIMARY KEY,
  contact_id INT NOT NULL REFERENCES contacts(id) ON DELETE CASCADE,
  flow_id INT NOT NULL REFERENCES flows(id) ON DELETE CASCADE,
  current_node_id INT REFERENCES flow_nodes(id) ON DELETE SET NULL,
  status TEXT NOT NULL DEFAULT 'running',
  variables JSONB NOT NULL DEFAULT '{}',
  save_field TEXT,
  timeout_job_id TEXT,
  updated_at TIMESTAMPTZ DEFAULT now(),
  UNIQUE (contact_id, flow_id)
);

CREATE TABLE IF NOT EXISTS message_logs (
  id SERIAL PRIMARY KEY,
  contact_id INT REFERENCES contacts(id) ON DELETE CASCADE,
  direction TEXT NOT NULL,
  action_type TEXT,
  content TEXT,
  created_at TIMESTAMPTZ DEFAULT now()
);
```

## Tipos de nó e ação

**node_type:** `start`, `message`, `wait_response`, `condition`, `tags`, `smart_interval`, `notification`, `approved_sale`

**action_type + config:**
- `send_message` → `{message_text}` — variáveis `{CAMPO}`, `{full_name}`, `{phone_number}`
- `send_multi_media` → `{media_type:'audio', media_file_info:{url, filename, content_type}}`
- `send_file` → `{file_name, media_file_info:{url, filename, content_type}}`
- `wait_for_response` → `{timeout_unit:'minutes'|'hours'|'days', timeout_value}`
- `save_user_data` → `{field_name}`
- `evaluate_condition` → `{ruleType:'any'|'all', conditions:[{category, fieldName, fieldValue, fieldOperator:'contains'|'equal', systemSubtype?}]}`
- `add_tags` → `{tags:[...], action:'add'|'remove'}`
- `smart_interval` → `{interval_unit:'minutes'|'hours'|'days', interval_value}`
- `send_notification` → `{name, phone, country_code, message}`
- `register_approved_sale` → `{amount_template, currency_template}`

**condition_config das conexões:**
- padrão: `{type:'always'}`
- respondeu (wait_response): `{type:'always', source_handle:'client-response'}`
- timeout (wait_response): `{type:'always', source_handle:'timeout'}`
- verdadeiro (condition): `{type:'always', condition_result:'success'}`
- falso (condition): `{type:'always', condition_result:'failure'}`

## Semântica do motor

1. `POST /webhook/evolution` recebe `MESSAGES_UPSERT` e `CONNECTION_UPDATE`.
2. Mensagem (`fromMe=false`, `@s.whatsapp.net`): upsert contato → se `waiting_response`, cancela
   job de timeout, salva resposta em `save_field`, segue `client-response`. Se não há estado,
   dispara fluxo ativo da instância por keyword ou `trigger_type=all`.
3. Runner: executa ações em ordem com delay 2–5s entre envios. `wait_for_response` e
   `smart_interval` são bloqueantes (job BullMQ na fila `flow-timeouts`, Redis do Coolify).
4. Interpolação `{X}` → `custom_fields.X`, `{full_name}`, `{phone_number}`.
5. URLs `/media/...` viram `PUBLIC_URL + url` na hora do envio.

## Cliente Evolution API v2

Header: `apikey: flowdev123`. Base: `http://localhost:8080`.

- `POST /instance/create` `{instanceName, qrcode:true, integration:'WHATSAPP-BAILEYS'}`
- `GET /instance/connect/{name}` → QR base64
- `GET /instance/connectionState/{name}` → `{instance:{state}}`
- `DELETE /instance/logout/{name}` / `DELETE /instance/delete/{name}`
- `POST /webhook/set/{name}` `{webhook:{enabled:true, url:'http://localhost:4300/webhook/evolution', events:['MESSAGES_UPSERT','CONNECTION_UPDATE']}}`
- `POST /message/sendText/{name}` `{number, text, delay}`
- `POST /message/sendMedia/{name}` `{number, mediatype, media, fileName, delay}`
- `POST /message/sendWhatsAppAudio/{name}` `{number, audio, delay}`

Webhook `MESSAGES_UPSERT`: `body.instance`, `body.data.key.remoteJid`, `body.data.key.fromMe`,
`body.data.pushName`, texto em `body.data.message.conversation` ou
`body.data.message.extendedTextMessage.text`.
